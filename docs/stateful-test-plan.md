# 状态操作测试范围与剩余条件

本页先列当前 PC 网页状态操作，再保留历史 App 记录。两个范围分别统计；历史 App 的主帖清理限制仍保留，不能被 PC 回复清理结果覆盖。

## 当前 PC 状态操作

| 能力 | 已验收范围 | 尚未覆盖 |
| --- | --- | --- |
| 点赞/取消点赞 | 帖子与普通回复分别读取基线、变化并恢复 | 楼中楼点赞未单独测试 |
| 普通回复、楼中楼及本人删除 | 创建后核对新编号、作者和父子关系；先删子后删父，回查未发现本轮内容 | 只覆盖本轮两条本人内容和所检查列表 |
| 收藏/取消收藏 | 未收藏基线下添加、回查变化、取消后恢复 | GET rmstore_pc、其他状态枚举未测 |
| 用户关注/取消关注 | 两受控账号的目标关系变化、回查并恢复 | 不代表贴吧关注通过 |
| 主帖、贴吧关注、签到、隐私/黑名单、媒体 | 仍有 PC 业务待验收项 | App 成功不能替代；具体状态见 [功能表](../README.md#功能) |
| 吧务管理 | 用户明确不测 | 不再申请管理员账号；本人测试回复删除另行验收 |

有效请求组合和清理判据见 [PC 基础功能](pc-web-basic-functions.md)，完整候选状态见 [PC CSV](pc-web-api-coverage.csv)。现有网页会话、指定帖子和测试吧足够继续普通功能；额外样本只按具体 PC 功能申请，见 [验收资源](acceptance.md)。

## 历史 App 状态操作

以下表格与剩余条件属于早期 App 测试，逐项结果以 [当前验证范围](remaining-validation.md)、[CSV](current-api-coverage.csv) 和 [脱敏报告](../evidence/comprehensive-validation.json) 为准。用户已授权测试，并明确排除吧务；未执行原因不再写成缺少授权。

| 能力 | 已观察结果 | 尚未覆盖的边界 |
| --- | --- | --- |
| 指定帖回复、楼中楼及本次内容删除 | 回读作者、标记和父子关系匹配，删除后两个编号返回空 | 见 [指定帖报告](thread-validation.md)，不代表所有内容类型 |
| 双账号关注与取消关注 | 关系变化与回查一致，原关系已恢复 | 见 [双账号报告](two-account-validation.md) |
| 收藏与取消收藏 | collect_status 从 0 到非零再回到 0 | 仅覆盖指定帖子和本轮账号 |
| 图片水印、消息屏蔽标志 | 设置变化与回查一致，原值已恢复 | 不代表已实现私信收发 |
| 隐私 opt=post | 请求 val=2 后读取为 3，恢复原值 1 | 已有变化及恢复证据，完整枚举映射未确认 |
| 贴吧关注与取消关注 | 第二账号从未关注到关注，取消后的延迟回查恢复 | 即时回查曾仍显示已关注，原因未定位 |
| 用户屏蔽 | 添加返回 1990043，明确需要高级会员；原状态未变 | 没有成功添加，删除成功响应只是幂等观测 |
| 指定吧签到 | 160002，服务端提示此前已签到 | 本轮未验证新增签到成功 |
| 小尾巴增改删 | 两轮样本创建、编辑及删除回查通过，原列表恢复 | 启用和停用均返回 3110002，明确要求贴吧会员 |
| 关注列表开关 | 读取原值后变化并恢复，回查一致 | 仅验证 2→1→2，不承诺完整枚举映射 |
| 本人新主帖 | 创建及对象回查通过；删除后主帖详情返回 4 | 首楼编号仍返回数据，进一步删除返回 230890，未通过完整清理 |

本人新主帖只创建了一条，位于用户链接对应的“[redacted-forum-name]”。具体编号和标记留在本机忽略目录；未继续创建新内容。名称包含 bawu 的本人删除接口不等同于管理员操作。

| 剩余范围 | 具体缺项 |
| --- | --- |
| 吧务管理 | 用户明确不测；保留既有观测并列为 excluded-by-user |
| 单聊、SDK 普通群聊 | 双向收发、回读、本人撤回及退出已完成；见 [IM 实测](im-validation.md)。公开聊天室、直播群发等仍需各自对象和协议 |
| 语音、部分视频、投票、活动和直播 | 缺少对应有效内容、房间或活动样本；图片代理通过不等同于这些能力通过 |
| 其他状态操作 | 各自的请求参数、有效目标或恢复步骤尚未建立；不能根据路径名执行 |
| 订单、购买、支付、账号清空或关闭 | 缺少隔离订单、沙箱或专用账号；未用真实扣款或清空账号来探测 |
| 遥测和日志状态 | 已有匿名空请求返回；真实事件字段、处理语义与后台可观测验收仍未完成 |

现有线上读取计划全部执行过，仍不表示全部候选可用。对象级断言、负对照、业务错误和未执行操作在当前清单中分别保留，原始响应和账号配置不进入 Git。

后续 249 次请求及业务验收缺项见 [补测报告](supplemental-validation.md)。该补测阶段的 184 条候选只有匿名诊断，后续 App 汇总为 176 条；其中请求构造分析尚未完成的项目明确保留，不写成服务端限制。
