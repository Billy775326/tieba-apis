# PC 点赞、回复、楼中楼与收藏

本页给出 PC 网页基础交互的已验证请求组合。2026-11-15（香港时间）新增 **26 次业务操作**，验证帖子/普通回复点赞及恢复、收藏及恢复、创建普通回复和楼中楼、删除本人测试内容并回查。完整证据见 [基础功能实测](../evidence/pc-web-basic-functions-validation.json)。

这些是已完成定向验收的业务能力；当前公开命令仍是只读验收工具，尚未提供通用 PC 写入 SDK。以下字段是本轮有效组合，不表示已经逐项证明字段可以省略。TBS、jt 和 Acs-Token 由已登录网页的官方请求封装生成，不导出到本机文件。

## 点赞和取消点赞

`GET /c/c/agree/opAgree_pc`，对应当前前端 `core:31.j`。

| 字段 | 本轮含义 |
| --- | --- |
| `thread_id` | 目标帖子编号 |
| `post_id` | 帖子点赞时为帖子编号；普通回复点赞时为回复编号 |
| `op_type` | 0 点赞，1 取消点赞 |
| `obj_type` | 3 帖子，1 普通回复；源码还有 2 楼中楼，但本轮没有单独测试楼中楼点赞 |
| `forum_id` | 目标吧编号 |
| `agree_type` | 本轮使用 2 |
| `obj_source` | 本轮使用 a005 |

分别读取帖子和普通回复的明确 has_agree 基线，执行变化后回查同一对象，再恢复并回查原值。不能只凭业务码 0 声称点赞状态已变化；也不能把点赞数的其他用户增减当作本账号的状态证明。

## 普通回复与楼中楼

`POST /c/c/post/add_pc`，对应当前前端 `core:1302.b`。

| 字段 | 普通回复 | 楼中楼 |
| --- | --- | --- |
| `tid`、`fid`、`kw` | 从目标帖子详情取得 | 同一帖子和吧 |
| `name_show` | 当前账号网页资料中的展示名 | 同左 |
| `content` | 本次唯一测试标记和正文 | 本次楼中楼标记和正文 |
| `quote_id`、`repostid` | 空字符串 | 均为本次创建的父回复编号 |

创建后使用返回的 pid 回读，不自动重试创建请求。普通回复使用 `GET /c/f/pb/getmypost_pc`，参数为 `last_pid=新回复编号, mark_type=2, kz=帖子编号`；本次回查的新编号、本人作者编号和内容标记均匹配。之前使用无有效本人回复定位对象的 getmypost_pc 返回过 210009，不能据此认定该接口不可用。

楼中楼使用 `POST /c/f/pb/nestedFloor`，参数为 `post_id=父回复编号, thread_id=帖子编号, offset=0`。已验证新楼中楼出现在该父回复的列表中，并核对本人作者与唯一标记。

## 删除本人测试回复

`GET /c/c/bawu/delpost_pc`，对应当前前端 `core:63.b`。

| 字段 | 本轮取值来源 |
| --- | --- |
| `fid`、`word` | 目标吧编号和吧名 |
| `z` | 目标帖子编号 |
| `pid` | 本次创建且回读核对过的回复或楼中楼编号 |
| `owner_uid` | 本轮使用 0 |

按先楼中楼、后父回复的顺序删除，两个请求均返回业务码 0。随后回查原楼层所在页面和父回复的楼中楼列表，没有发现本次创建的编号或标记。删除验收只覆盖这两条本人测试内容；不涉及管理员删除他人帖子，也不将本人回复删除结果推广到删除主帖。

删除/楼中楼参数还参考了前期留存的 PC 帖子页脚本；原 URL 未保留，报告只记录其摘要并明确该来源边界。本轮当前网页的实际请求和回读是上述可用性结论的依据，没有补造公开源码地址。

## 收藏和取消收藏

`POST /c/c/post/addstore_pc` 对应 `core:1302.a`，表单 data 为 JSON 字符串数组，本轮每项包含：

```json
[{"tid":"帖子编号","pid":"首楼编号","status":1}]
```

这是字段示意，不能将占位文字作为编号发送。本轮只在明确未收藏（collect_status=0）的基线执行，添加后回查 collect_status 已变化。

`POST /c/c/post/rmstore_pc` 对应 `core:1302.d`，本轮传 `fid`、`tid` 和帖子作者 `uid`。取消后回查 collect_status 恢复原值。GET 版本的 rmstore_pc 虽也有源码声明，本轮没有调用；其他收藏状态枚举和覆盖已有收藏定位信息的行为也没有据此判为通过。

## 本轮边界

- 点赞、普通回复点赞和收藏均已恢复原状态；两个测试内容均按上述 PC 回读范围完成清理。
- 测试标记、新回复编号和恢复登记只保存在忽略目录，不提交到公开证据。
- 发主帖、删除主帖、关注贴吧、签到、搜索及媒体写入仍有单独待验收项，见 README 的[功能表](../README.md#功能)。
- 原有读取验收命令没有新增写入行为；运行 `verify:pc` 不会触发这里的发回复、点赞或删除测试。
