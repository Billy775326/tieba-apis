# 提交隐私规范

本项目禁止在提交内容中保存真实账号信息、测试对象及凭据。允许本机被忽略的 `.local/` 保存登录态、原始响应和恢复清单；本规范不要求删除这些本机数据。

## 可提交内容

- 接口路径、协议字段、官方公开常量、软件版本、源码引用及产物摘要。
- 经过脱敏的实测时间、业务码、数量、对象匹配布尔值与恢复结论。
- 明确用于离线测试的合成数据。合成对象不能冒充线上实测对象。

真实账号编号、用户名、portrait、邮箱、手机号、测试帖和回复编号、测试吧名、唯一测试内容、个人目录以及 Cookie、Token、密码均不得提交。证据文件名也不能包含真实对象编号。历史报告保留实际观测，只移除目标标识；脱敏不代表重新执行了线上测试。

## 本机输入与检查

PC 读取必须显式传入 `--thread`，可选传入 `--forum`，没有真实目标默认值。文档中的 `TIEBA_TEST_THREAD`、`TIEBA_TEST_FORUM` 由本机环境设置，PowerShell 展开为命令参数；历史匿名读取脚本直接读取后者。不要把实际值补写进示例或文档。

在仓库根目录执行：

```powershell
npm.cmd run check:privacy
# 审核差异并按文件暂存后，核对实际准备提交的 index：
node scripts/check-privacy.mjs --staged
```

默认检查 Git 已跟踪及已暂存新增文件的工作树内容；`--staged` 从 index 读取全部文件，不会被暂存后修改的工作树内容掩盖。尚未暂存的新增文件仍需人工审核，暂存后必须再检查。忽略目录不被递归扫描；若 `.local/` 被强行加入跟踪则检查失败。

检查覆盖证据中的对象标识字段、带编号的资源文件名、真实帖子 URL、个人 Windows 路径、私钥及字面凭据。可选在本机 `.local/privacy-denylist.json` 保存字符串数组，补充真实吧名、目标编号或唯一测试标记；每项至少四个字符。该文件不得提交，也不应为检查另行汇总或复制登录凭据。诊断只输出规则和位置，不回显命中的值。

检查不能识别所有自然语言个人信息，不能替代对新增文件和实际暂存差异的人工审核。测试中只有指定文件内的固定合成帖子 URL 被放行；不能借测试目录存放真实对象。

## Git 历史边界

经项目所有者明确授权，本轮清理受控分支的历史提交，移除真实测试目标及含编号的证据文件名，保留原实测结果、提交作者和时间。历史重写改变了相关提交及其后代的哈希；现有旧克隆应重新克隆，不要直接合并或推送旧历史，以免重新引入已清理内容。

原历史恢复包和引用清单仅保存在本机被忽略的 `.local/history-cleanup-*/`，不推送到远端。该备份有意保留旧内容，符合本机忽略目录可保存真实数据的约定。登录态、原始响应和恢复清单不随此次 Git 历史清理删除。

分支历史清理不等于平台端所有副本已被擦除。GitHub 的旧 PR 内部引用为只读，按旧提交哈希访问的缓存及其他人的克隆也不会随强制推送消失。服务端清除需要 GitHub Support 处理，是否受理由其数据敏感性与风险判定；参见 [GitHub 历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
