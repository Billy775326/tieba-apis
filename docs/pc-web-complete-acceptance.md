# PC 扩展验收与剩余限制

后续独立 HTTP 请求、刷新后回读及发主帖直接构造见 [直连专题](pc-web-direct-http.md)。本文当轮执行方式与结果保持历史含义。

本轮在两个现有网页登录会话中，对冻结的 86 个路径/方法候选继续定向验收，范围只含 PC 网页。新增 **249 条业务响应、44 个测试阶段**，累计 390 条记录；82 个候选已请求，62 个有对象或状态证据。**这不表示全部接口通过，也不表示全部写入已恢复。**

请求、业务码、响应摘要、断言及失败阶段见 [本轮 JSON](../evidence/pc-web-complete-acceptance.json)；累计结果见 [总报告](../evidence/pc-web-validation.json) 和 [86 项 CSV](pc-web-api-coverage.csv)。前 141 条历史记录原样保留。

## 已完成的受控流程

| 功能 | 实际验证与恢复范围 |
| --- | --- |
| 个人简介 | 保留原昵称和性别，仅修改简介，回读后恢复原简介；不测试昵称冷却 |
| 隐私与黑名单 | 关注吧列表隐私值切换并恢复；仅对受控第二账号切换 interact，保持 follow 权限原值，再恢复 |
| 徽章 | 槽位已满，改为摘下当前有效自有徽章，再原槽佩戴，核对原佩戴集合恢复 |
| 移除粉丝 | 第二账号临时关注第一账号；第一账号仅移除此受控粉丝；第二账号回读恢复为原未关注状态 |
| 主帖主页可见性 | 对本次自有主帖切换 private 并恢复；这是主页展示设置，不能解释为帖子访问权限控制 |
| 收藏 | 新主帖收藏后回查，再用 GET rmstore_pc 取消并核对；原 POST 取消证据保留 |
| 通知 | 第二账号在第一账号本次主帖点赞、普通回复、提及；三类 GET 通知均匹配对象；POST 提及与回复也匹配，POST 获赞未取得同一受控事件证据 |

| 帖子和回复清理 | 本轮唯一主帖、第二账号两条回复及第一账号一条图片回复已删除；主帖详情及预验证首楼定位删除后均返回 4 |
| 网页版本 | status=0 后页面外壳切到旧版，status=1 后恢复新版；3 次页面读取分别核对 |

## 错误与未验证项

| 接口或分支 | 实测与限制原因 |

| commitgood_pc、commitprison_pc、committop_pc | 账号实际吧务角色为零，用户也确认没有吧务账号；3 项管理写入未执行。普通账号授权无法提供平台角色 |
| goodlist_pc、getDeleteReason_pc、listreason_pc | 分类读取返回 0；删除原因 210009、禁言原因 300000。不能只凭这些业务码断言原因就是权限不足 |
| adNewLog | 正常滚动真实网页未捕获目标曝光请求，缺少真实广告事件上下文；未伪造广告点击或用空参数冒充有效测试 |
| score/addScore | 找到真实 thread_type=75 评分帖和有效评分项目；原 my_score=0，提交 score=0 返回 110003，回读仍为未评分。正向评分及撤回语义未验证，未留下虚假永久评分 |
| portrait_pc | 用当前原头像原字节提交，返回 300003；去掉查询后缀后原头像标识保持。未证明该码代表账号限制，也未验证异步审核完成 |
| picture/list | 本次自有图片回复已实际回读，接口仍返回 4444；缺少图片样本不能解释此结果，服务端原因待定位 |
| recomSiteTids | 使用官方默认 pageFr 空字符串仍为 210009；不能推断为安卓或会员限制 |
| generalTabList_pc | 源码字段修正后为 0，但 page_data 为空；原 300000 保留，非空业务分支未通过 |
| userAgree_pc | 非空 thread_list 已取得，但抽样线程级 has_agree 不能对应列表状态；需要区分 top_agree_post 与回复点赞，当前保留结构级结果 |
| 其余结构级读取 | 首页推荐、配置、发帖配置、候选吧列表、URL 解析等已保存实际响应结构；没有目标/完整流程证明的项目仍不提升层级 |

新的普通账号、密码或安卓设备不是当前读取与一般写入的前提。吧务资源用户已明确没有；服务端业务错误、调用语义和参数恢复属于工程排查，不能统一归咎于账号或再次申请笼统授权。

## 参数与证据使用

完整已核对组合见 [API 表](api.md#pc-已验收请求契约)。以下差异尤其影响复现：

- threadlist_pc 使用 forum_id、forum_name、frs_common_info、逗号分隔的 thread_ids 与 sort_type；forum.tids 是字符串。按实际字段恢复后已返回请求中的帖子。
- myThread 使用 portrait、pn、rn、type 和 un；新主帖进入主页索引有延迟，不能把立即未出现当成发帖失败。返回 list，收藏/点赞列表使用 thread_list，关注列表使用 follow_list。
- @ 建议使用 word 与 rn=100；话题建议使用 is_video_topic=0、prefix。先前错误入参保留，不当作账号限制。
- 图片上传字段包括 resourceId、isFinish、saveOrigin、size、width、height、chunkNo、pic_water_type 和 chunk 文件；AI 使用 article_content、pipeline=test。封面裁剪框与正文图片上传入口不同，首次错误入口未发出目标请求。
- 官方安全 SDK 尚未就绪时，发帖停在实际发送前；取消迟到发送、清空本次未发布草稿并重新初始化官方 SDK 后成功。未自动重试创建请求。

本轮补充固定 home-main、pb、publish 和公共发布组件脚本的官方 URL、大小与 SHA-256，见 JSON 的 auxiliary_sources。源码表中的 moderation-role-required 表示角色条件；旧报告当时的排除描述作为历史保留。

公开 verify:pc 仍为固定只读白名单，未新增通用写入 CLI 或 SDK。写入定向工作流中的请求参数、编号和回查范围均须按对应版本的证据使用。
