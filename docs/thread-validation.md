## 复测

在仓库根目录使用 Node.js 24+，不需要登录态或额外 npm 依赖。本机环境变量 `TIEBA_TEST_THREAD` 必须设置为实际目标编号或官方帖子 URL；仓库不提供真实目标默认值：

```powershell
node scripts/verify-thread.mjs --live --thread "$env:TIEBA_TEST_THREAD"
```

也可以把 `--thread` 后的值换成十进制帖子编号。脚本只接受官方帖子 URL 或正 int64 编号；输出写入 `.local/thread-<编号>-verification.json`，原始响应使用独立文件名，不覆盖首批公开样本。缺少楼中楼样本、响应不匹配、请求或解码失败时，不判为整轮通过。公开帖子可能被编辑、删除或限制访问，复测需按实际返回判断。

## 登录回复、楼中楼与清理实测

2026-11-14 香港时间 09:42–09:45，以已扫码账号对同一帖子执行定向写入验证。App 的带登录态 PbPage 响应中的 User.id 与官方网页当前登录 user_id 相同，并从 anti.tbs 取得 TBS；未使用此前未匹配身份的 open_uid 猜测值。这个身份核对只证明本轮接口接受了当前账号，不代表所有账号接口均可用。

| --- | --- | --- |

| 对自己的测试回复创建一条楼中楼 | 同一 AddPost 接口，补 quote_id、repostid、reply_uid | 业务码 0；回读编号、作者、标记匹配，PbFloor 确认位于测试父回复下 |

脱敏时间、响应摘要与逐次结果见 [写入及清理报告](../evidence/thread-fixture-write-validation.json)。共创建两条内容，删除两条，回查没有遗留测试内容。原始响应、唯一测试标记、回复编号、账号编号与凭据只保存在本机忽略目录。

AddPost 的路径、cmd、字段编号与编码来自 APK 的构造函数、encode 方法及 Wire 注解。最小请求在 CommonReq 中携带 BDUSS、客户端类型/版本、时间戳、TBS 和 pversion；DataReq 中传 tbs、tid、fid、kw、content、anonymous=0、can_no_forum=0。楼中楼的 quote_id 与 repostid 均指向本轮父回复，reply_uid 指向已核对的当前账号。

删除路径来自 APK 字符串，表单签名来自已恢复的 NetWork.addSign；本轮使用 BDUSS、客户端类型/版本、时间戳、tbs、fid、kw、word、z、pid、owner_uid=0。pid/fid/z/word/owner_uid 还参考了官方 PC 自身回复删除处理器，但实际调用的是不带 _pc 的客户端路径，不是网页删除接口。当前 JADX 未恢复 APK 删除任务的方法体，因此不能声称全部删除参数都已从 APK 方法体中恢复。

首次父回复作者检查使用 Post.author_id，该响应未返回该字段；按 APK 的内嵌 Post.author.id 核对后才确认作者一致并继续。缺失作者字段不作为身份匹配。读取时 rn=1 曾得到业务码 29，改为 rn=20 后正常；故不能把该错误单独解释为登录失效。

写入由本机 .local 下的定向脚本执行，没有加入可任意写入的通用 CLI；现有 verify-thread.mjs 仍仅执行读取。写入请求不自动重试，创建前保存尝试状态，删除仅接受本轮返回、已回读核对的编号。后续复测需另建本轮记录，不能复用已经删除的编号。

## 后续测试还需要什么对象

该帖不是测试账号发布的。用户已明确允许在其中创建测试回复、楼中楼，并仅删除本次创建的内容；本轮已完成该范围验证，无需再提供普通回复测试帖。后续用户已提供测试吧并完成本人新主帖测试；详情删除后首楼仍能按编号读取，见 [当前删除限制](remaining-validation.md#测试主帖的删除限制)。
